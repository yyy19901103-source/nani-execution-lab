## 1. 機能要件

### 1.1 フィルタ条件（複数選択可・AND結合）
| フィルタ | 選択肢 | データ元 |
|---------|--------|---------|
| センサー種別 | ランプ色 / 電流 / 重量 / 振動 / 音 / 温度 / RFID / 画像 | PDF章別 |
| 取付難度 | ★ / ★★ / ★★★ | PDF費用×種別から推定 |
| 初期費用帯 | 〜5万 / 5-20万 / 20-60万 / 60万〜 | PDF費用表 |
| 自律化貢献 | 入口 / 中核 / 周辺 / 応用 | PDF自律ロードマップ |
| 主目的 | 停止削減 / 在庫 / 保全 / 品質 / 安全 / トレーサビリティ / エネルギー | PDF分析手法 |
| 中学生実行可 | ◯ / △ / × | 新規付与 |

### 1.2 結果表示
- カード形式（既存 `/ai-tools/eto-similar-quote` の結果表示を踏襲）
- カードあたり: タイトル / センサー種別バッジ / 費用レンジ / 中学生実行可マーク / 主要KPI
- カードクリック→詳細モーダル: 取得データ / 分析手法 / 前処理 / 評価指標 / 運用効果 / リスク / 中学生実行手順

### 1.3 詳細モーダルの中身（160件分）
```typescript
interface UseCase {
  id: string;              // "lamp-01" "current-01" など
  sensorType: SensorType;  // 8種
  no: number;              // 1-20
  title: string;
  acquired: string;        // 取得データ
  method: string;          // 分析手法
  preprocessing: string;   // 前処理・ラベル・評価
  operation: string;       // 運用効果
  cost: { min: number; max: number };  // 万円
  risks: string[];
  difficulty: 1 | 2 | 3;
  contribution: 'entry' | 'core' | 'edge' | 'advanced';
  purpose: Purpose[];
  studentLevel: 'ok' | 'partial' | 'no';
  studentSteps?: {         // 中学生実行版
    tools: string[];       // 道具と価格
    steps: string[];       // 5ステップ
    aiPrompt: string;      // そのまま貼れる
    verification: string;  // 答え合わせ
    nextStep: string;      // 進む条件
  };
}
```

### 1.4 追加機能
- **CSV エクスポート**: 絞り込み結果を社内検討用にDL
- **シェアリンク**: フィルタ条件をURLパラメータ化（`?sensor=current&cost=0-5`）
- **比較モード**: チェックを入れた3件を横並び比較
- **「私の現場で使えそう」ブックマーク**: localStorage 保存

## 2. データソース設計

### 2.1 データ配置
- `src/data/iot-usecases.ts` — TypeScript 配列で 160 件定義
- 約30KB（typed JSON より型安全・ビルド時定数として埋込）
- 中学生実行版（160 × 5項目 = 800 項目）は別ファイル: `src/data/iot-usecases-student.ts`（約60KB）

### 2.2 データ抽出元
- PDF 24p の8章 × 20ケース表 → 機械的に抽出
- 中学生実行版: 第3話・第4話執筆時にブログ内コラムから抽出して再利用

### 2.3 機密保護フィルタ
- ❌ 拠点名・型式・実数値は全削除
- ❌ MQTTサンプルの `hiroshima01` → `site_a` 置換
- ✅ 業界用語（デビクラ・RFQ・Project・WIP）は許容
- ✅ 公開済海外事例の引用は許容（Tractian / Augury / MVTec / Opto 22）

## 4. 実装工程

### Phase 1: データ整備（先行）
1. PDF 8章 × 20ケース → `iot-usecases.ts` 機械抽出（推定2時間）
2. 機密保護フィルタ通過チェック（30分）
3. 各ケースに difficulty / contribution / purpose / studentLevel をタグ付け（推定1.5時間）

### Phase 2: UI 実装
4. 既存ツール `eto-similar-quote.astro` をベースにレイアウト構築（推定2時間）
5. フィルタロジック実装（クライアントサイド・LocalStorage）（推定2時間）
6. 詳細モーダル実装（推定1.5時間）
7. CSV出力 / シェアリンク / 比較モード（推定2時間）

### Phase 3: 中学生実行版データ
8. 第3話・第4話執筆と並行して 160 × 5 項目を埋める（ブログ執筆と兼ねる）

### Phase 4: 検証
9. WCAG AA フォーカスリング確認
10. モバイル表示確認
11. 機密保護 grep（`hiroshima` / `MCO` / 個人名検索）
12. CODEX 9巡目に同梱依頼

**総工数見積**: 約12時間（Phase 3を除く・データ抽出が機械化できれば短縮）

## 5. ToolLayout 化（D-1 タスク）との関係

このツールは D-1 の最初の検証対象として最適:
- 既存10ツールと完全に同じ骨格（機密バナー・クイックスタート・USE CASES・本体・NEXT ACTIONS・このツール・3点セット）を持つ
- 新規実装なので、ToolLayout を**先に作ってから**このツールを移植先1号にできる
- 既存10ツールの後追い改修よりリスクが低い

### D-1 着手順序の修正案
1. `src/layouts/ToolLayout.astro` を新規作成（props: title, description, subtitle, heroBg, quickStartPresets, useCases, nextActions, aboutSections）
