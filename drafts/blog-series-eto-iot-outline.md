# 第1話: なぜ一品一様製造のIoTは"平均値管理"では失敗するのか

**スラッグ**: `2026-05-12-eto-iot-why-context-matters`
**字数目安**: 5,000字
**読了時間**: 12分
**主タグ**: ETO / IoT / 設計思想
**heroImage 候補**: 重工業の鍛造設備（Unsplash検索: `forging factory`）

## TL;DR（3行）
1. 量産工場のSPC（統計的工程管理）をETO（一品一様）に持ち込むと、案件ごとの違いを「ノイズ」として捨ててしまい予測が当たらない
2. `asset_id` だけでなく `project_id` / `process_step` / `material_lot` / `operator_band` を**特徴量**に組み込む「案件文脈付き異常検知」が必要
3. 後付けセンサーと新規設備調達を**最初から別ルートで設計**し、共通データ契約で収束させるのが2026年の合理解

## h2 構成
### 1. 量産工場のKPIをコピペしてはいけない理由
- 3.1 OEE（設備総合効率）だけでは見えない4つの損失（探索・段取り・判定遅れ・誤投入）
- 3.2 経産省ものづくり白書2025の「個別受注生産」分類
- 3.3 ETOで本当に効くKPI（探索時間 / 案件単位在庫信頼度 / 設備選定適合率）

### 2. 案件文脈付き異常検知という発想転換
- 「同じ設備でも案件が違えば正常範囲が変わる」具体例
- 特徴量に project_id を入れるだけで何が変わるか
- ラベルが少ない現場でも回す方法（正常データのみ学習）

### 3. 二重路線設計 — なぜ後付けと新規調達を分けるか
- 既存設備ルート: 非侵襲・監視のみ・PoC優先
- 新規設備ルート: OPC UA / MTConnect 必須・10年後を見る
- 共通データ契約（MQTT/REST）で最後に収束

### 4. 自律製造への接続点
- 「情報収集→解析→行動決定→機構制御」4段ループの位置づけ
- 第5話への伏線

# 第2話: 既存設備に後付けする8種センサーの選び方

**スラッグ**: `2026-05-14-eto-iot-sensor-selection`
**字数目安**: 6,000字
**読了時間**: 14分
**主タグ**: IoT / 後付け / PoC
**heroImage 候補**: 信号灯（Unsplash: `andon stack light factory`）

## TL;DR（3行）
1. 短期PoCの最優先は**信号灯 + 電流 + 重量/RFID** — 設備に手を入れず、効果が即出る
2. 中期で振動・音・温度・画像を足すと予知保全・品質管理に広がる
3. ESP32（¥1,500）+ MEMSセンサーで世界最先端の研究を個人レベルで再現できる時代

## h2 構成
### 1. なぜ最初の3つは信号灯・電流・重量なのか
- 1.1 非侵襲性（設備の改造が要らない）
- 1.2 ROI最短ルート（120万円→6.1ヶ月回収の根拠）
- 1.3 失敗してもダメージが小さい

### 2. 8センサー比較表
| センサー | 初期費用 | 取付難度 | 即効性 | 自律化貢献 |
|---|---|---|---|---|
| 信号灯 | 2-8万円 | ★ | ★★★ | 入口 |
| 電流 | 1-5万円 | ★★ | ★★★ | 中核 |
| 重量 | 2-15万円 | ★ | ★★★ | 在庫系 |
| 振動 | 5-25万円 | ★★ | ★★ | 保全 |
| 音 | 2-10万円 | ★ | ★★ | 安全 |
| 温度 | 2-10万円 | ★ | ★★ | 品質 |
| RFID | 5-40万円 | ★★★ | ★★ | 追跡 |
| 画像 | 5-60万円 | ★★ | ★ | 検査 |

### 3. 世界2026最前線の超低コストキット
- ESP32（¥1,485〜）+ MEMS加速度計（¥800〜）+ マイク
- M5Stack シリーズ（¥3,500〜）でディスプレイ付き完結
- Raspberry Pi 5（¥12,000〜）でAI推論まで現場完結
- 海外事例: Tractian / Augury / Opto 22 groovRIO の実装パターン

### 4. PoC設計15項目チェックリスト
- 課題定義1つに絞る
- 文脈キー必須セット
- 時刻同期（NTP）
- データ品質コード
- フィードバックループ
- セキュリティ（X.509/TLS/RBAC）
- 退出基準

### 5. ヤってはいけない3パターン
- センサー先行（KPIが無い）
- ラベル過信（教師データが足りない前提を忘れる）
- ロックイン（ベンダ独自プロトコルで囲い込まれる）
